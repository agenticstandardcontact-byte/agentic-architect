How to choose a mini PC for local LLMs

Spec sheets lead with CPU cores and NPU TOPS. For running language models locally, neither is what limits you. Two numbers do: how much memory the model can use, which decides what you can load at all, and how fast that memory is, which decides how quickly it answers.

1. Memory size decides which models you can run

A model's weights take roughly parameters × bits per weight ÷ 8 bytes. Most people run 4-bit quantised models (for example GGUF Q4_K_M), which works out at roughly 0.6 GB per billion parameters once you include the format's overhead. Then add room for the context window (the KV cache grows with context length), the operating system, your IDE and any Docker containers.

Model sizeApprox. 4-bit fileComfortable system memory
7B–8Babout 5 GB16 GB
14Babout 9 GB32 GB
30B–32Babout 18–20 GB32 GB (tight) or 64 GB
70Babout 40–43 GB64 GB minimum

On integrated graphics and Apple Silicon the GPU shares system memory, so the whole pool is available, minus whatever the OS reserves. With a discrete or external GPU, only the model layers that fit in VRAM run at GPU speed; the rest spill to system RAM and the CPU.

2. Memory bandwidth decides how fast it answers

Generating each token means reading (nearly) every weight of a dense model from memory. That makes bandwidth divided by model size a hard ceiling on tokens per second; real-world speed lands below it. The ceiling explains most of the differences between machines:

Mixture-of-experts models read only their active parameters per token, so they run much faster than their total size suggests, which is why MoE models are popular on mini PCs. Prompt processing (reading a long prompt before the first token) is compute-bound rather than bandwidth-bound, and that's where a real GPU pulls ahead.

3. Integrated GPU, eGPU or unified memory?

  • Radeon integrated graphics (780M, 890M and newer) share system RAM, so a 64 GB machine can load large models. Ollama supports these GPUs through Vulkan on Windows and Linux, and Ryzen AI 300-series chips such as the HX 370 through ROCm on Linux. Bandwidth is the limit.
  • OCuLink external GPU (for example on the UM890 Pro) gives you a desktop card's fast VRAM. Excellent for models that fit inside that VRAM, much less so for ones that don't.
  • Unified memory (Apple Silicon, AMD Ryzen AI Max) combines a large pool with high bandwidth. It's the most practical way to run 30B–70B-class models on a small, quiet box.

4. NPUs: useful, but only with the right software

The 50 TOPS NPU in Ryzen AI 300-series chips can run LLMs through AMD's Ryzen AI software and the Lemonade server, either NPU-only or in a hybrid mode where the NPU processes the prompt and the iGPU generates tokens. It's power-efficient and good for background tasks. Mainstream runners like Ollama use the GPU or CPU instead, and older Ryzen 7000/8000 chips (including the 8945HS in the UM890 Pro) have no NPU path for LLMs. Treat TOPS as a bonus, not the reason to buy.

5. Intel Arc or AMD Radeon?

Both run local models through llama.cpp-based tools using Vulkan, and each vendor maintains its own optimised stack on top. On a mini PC the GPU brand matters less than the memory behind it: compare capacity and bandwidth first, then check that your preferred runner lists your exact GPU.

6. What a .NET developer actually needs

If the machine also runs your IDE, a few Docker containers (SQL Server, Redis, a message broker) and a test suite, budget 8–12 GB for that before the model. That makes 32 GB the practical minimum for pairing development with a 7B–14B model, and 64 GB the sensible target if you want 30B-class models alongside your containers. Be realistic about the role, too: local models are excellent for private autocomplete, embeddings, summarising logs and offline work, but the strongest agentic coding models are still cloud-only. FAQ

How much RAM do I need to run a local LLM on a mini PC?

At 4-bit quantisation a model needs roughly 0.6 GB per billion parameters, plus room for context and the operating system. In practice 16 GB runs 7B–8B models, 32 GB runs 14B comfortably and 32B tightly, and 64 GB is the floor for 70B-class models.

Is a mini PC good enough for Ollama?

Yes for 7B–14B models, which run at usable speeds on recent AMD mini PCs with Radeon integrated graphics; Ollama supports these GPUs through Vulkan, and Ryzen AI 300-series chips through ROCm on Linux. Larger models fit in 64 GB of RAM but generate slowly unless the machine has high memory bandwidth, such as Apple's unified memory or AMD Ryzen AI Max systems.

Intel Arc or AMD Radeon for local AI development?

Both work for local LLMs through llama.cpp-based runners using Vulkan, and each vendor also has its own optimised stack. On a mini PC, memory capacity and bandwidth matter more than the GPU brand, so compare those first.

Does the NPU in a mini PC speed up local LLMs?

Only with specific software. AMD's Ryzen AI software and Lemonade can run models on the NPU, or split work between NPU and iGPU, on Ryzen AI 300 and 400 series chips. Mainstream runners such as Ollama use the GPU or CPU, and older Ryzen 7000/8000 chips have no NPU path for LLMs, so don't buy on TOPS alone.
